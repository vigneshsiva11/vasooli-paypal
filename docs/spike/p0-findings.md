### Distinctions & Caveats (Observed vs Documentation)

- **Transaction Identification [OBSERVED]**: A PayPal-paid payment has `payments.transactions[].type` `"PAYPAL"`, `method` `"PAYPAL"`, `transaction_type` `"SALE"`, and `transaction_status` `"SUCCESS"`. In contrast, a recorded external payment has `type` `"EXTERNAL"`, `method` matching the recorded method (`BANK_TRANSFER`), includes `note`, and omits `transaction_type` / `transaction_status`. Distinguishing PayPal-paid from external payments can be done via `payments.transactions[].type` (`PAYPAL` vs `EXTERNAL`) and `method`.
- **Partial Payment Webhooks [OBSERVED]**: The event type `INVOICING.INVOICE.PAID` also fires for PARTIAL payments, confirmed by observed event `WH-99238613G8280990B-9FV78269C92473434` (`event_type` `INVOICING.INVOICE.PAID` with invoice `status` `PARTIALLY_PAID`, `paid_amount` `10.00`). Consequently, receiving `INVOICING.INVOICE.PAID` does not imply full settlement; systems must check invoice `status` (`PARTIALLY_PAID` vs `PAID`) and `due_amount` / `paid_amount` to determine whether the invoice is settled.
- **Timestamp Caveat [OBSERVED]**: There is an observed 7-hour gap between `payments.transactions[].payment_date_time` (`08:50:08Z`) and the webhook event `create_time` (`15:50:16Z`). The Pacific-time cause (PDT is UTC-7) is inferred, as PayPal returns the local time with a misleading `Z` suffix. In contrast, `metadata.last_update_time` is correct UTC. Always use the event `create_time` or `metadata.last_update_time` for authoritative timing.

## Notes on quotas and limits observed

- Invoice API: no hard cap observed in sandbox for create/send.
- Orders API: no rate-limit hit during spike.
- Vault: sandbox returns vault id inline in capture response for the first
  successful vault. Subsequent vault listings require
  `GET /v3/vault/payment-tokens/{vault_id}`.
- PayPal sandbox verifications (`/v1/notifications/verify-webhook-signature`)
  do NOT work for mock/manual webhook events sent via the dashboard's
  "Send test notification" — they require a real in-flight event.
- Token expiry: 32400 seconds (~9 hours) as observed in p0_token_check.py.
